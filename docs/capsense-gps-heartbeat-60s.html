Meshtastic · Quick setup

CapSense: broadcast GPS position every 60 s

App-only setup. Starting point: node already on the LONG_MODERATE preset, role CLIENT.

2Position — the heartbeat

SettingValueWhy
GPS ModeEnabled Not Disabled, not Not present.
Position Broadcast (s)60 The heartbeat. Default is 15 min. 0 means "default", not "zero".
Smart PositionOFF ON by default. It adds extra transmissions whenever you move ≥100 m (min 30 s apart), on top of the 60 s beacon. Off = exactly one packet per minute, which is what you budgeted airtime for.
Fixed PositionOFFWould ignore the real GNSS.
GPS Update Interval30 Default is 2 minutes — leave it and every other beacon repeats stale coordinates. Must be ≤ 60.
Position flagsMinimum Each flag adds bytes to 1,440 packets/day.
GPS RX / TX pinDon't touchSet by the stock firmware.

Tap Save. The node reboots and BLE drops for a few seconds — normal. Nothing applies until you save.

3Channel

Radio configuration › Channels › primary channel (index 0)
SettingValueWhy
Position precision / Location sharingPrecise This is a 0–32 precision value, not a simple toggle: 0 = location never sent on this channel, 32 = full precision, values in between snap you to a privacy grid. If it reads Do not share, the beacon carries no coordinates.

Save. Do not change the channel name or PSK — the node would drop off your mesh.

4Power

Radio configuration › Power
SettingValueWhy
Power SavingOFF Sleep cycles cut the GNSS between beacons and make the heartbeat irregular.

Save. That is the last configuration screen.

5Verify

  1. Outdoors, wait for the first fix — 1 to 5 minutes on a cold start. The very first beacon after boot is skipped until a fresh fix exists.
  2. Nodes tab › your CapSense: coordinates and a recent timestamp.
  3. Watch last heard for 3–4 minutes: it must reset every ~60 s.
  4. Real check: connect the app to a different node and confirm the CapSense shows up there refreshing every minute. That proves the LoRa path, not just Bluetooth.

●Why it may still not beacon every 60 s

Two firmware rules override your setting. Neither shows an error in the app — the beacon just doesn't go out.

RuleEffect
Channel utilisation gate Position packets are dropped while channel utilisation is ≥ 25 % for the Client role (Tracker roles get 40 %). A busy mesh silently stops your heartbeat.
Node-count scaling Above 40 online nodes the firmware stretches the interval automatically. On LONG_MODERATE the factor is 1 + 0.16 per extra node: 50 nodes → ~2.6× (≈158 s), 60 nodes → ~4.3× (≈257 s). You cannot hold 60 s on a large mesh.
SymptomFix
Node visible, no positionNo GPS fix. Go outdoors, wait 5 min. Confirm GPS Mode = Enabled.
Beacons every 15 minThat's the default — Save didn't apply. Reconnect, re-enter 60, Save.
Extra beacons while movingSmart Position still ON.
Same coordinates repeatedGPS Update Interval > 60 s. Set it to 30.
Other nodes don't see itChannel position precision at 0, or mismatched region / preset / channel PSK, or TX disabled.
Cost on LONG_MODERATE

0.34 kbps: each position packet holds the channel for roughly 1.5–2 s, so one node alone sits near 2–3 % utilisation continuously, multiplied by every rebroadcast and hop — which feeds straight into the 25 % gate above. Battery with the GNSS always on lasts hours, not days. Use 60 s only on the node you are actively tracking; 120–300 s otherwise.
